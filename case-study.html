TA Manager Dashboard

A zero-backend sales intelligence tool consolidating 847 target accounts and 6,294 leads across four account managers — built, deployed, and automated end-to-end.

Context
Four managers. No unified view.

Growisto's Target Account team each maintained separate prospecting workflows inside Zoho CRM — switching modules, filtering by owner, manually cross-referencing accounts to leads. There was no visibility into which accounts were warm, which had contacts attached, or whose follow-up was already overdue.

The requirement was a single-page dashboard showing each manager's full portfolio with filtering, priority ranking, and contact coverage — shareable as a URL, no login required.

Architecture
Static HTML as the entire deployment target.

The core decision: embed all CRM data as a JSON literal inside the HTML at build time. No backend, no auth middleware, no API gateway. The dashboard loads in one request and works offline once cached.

Engineering
Four problems worth documenting.
Finding 01
The lead filter was wrong for two of four managers

Initial COQL queries filtered by Lead.Owner.id — the user who entered the record. For two managers, this returned zero leads because another team member had created those records.

Before: filters by who created the lead record
SELECT * FROM Leads WHERE Owner.id = '319412...'
→ returned 0 leads for 2 of 4 managers
After: filters by who owns the linked Target Account
SELECT * FROM Leads WHERE Target_Account_Name.Owner.id = '319412...'
→ returns the correct full portfolio
Finding 02
Maira's dataset required 15 sequential paginated fetches

Zoho's COQL API caps results at 200 records per call. Maira's portfolio alone spanned 2,958 leads across 15 requests, each checking more_records before advancing the offset. Total: 8 pages for Siddharth (1,465 leads), 7 for Himanshi (1,239), 4 for Chitrakshi (632).

Finding 03
API responses above ~60 KB were silently truncated on disk

Large responses got cut mid-record when persisted to disk. A recovery script scanned each file backwards for the last valid },{ JSON record boundary, closed the array there, and re-parsed — recovering 189 of 200 records from one truncated 63 KB payload.

Finding 04
22 accounts existed in leads but not in the account query

Chitrakshi's account query returned 333 records; her leads referenced 22 additional account IDs absent from that set — likely CRM ownership gaps. The build script derives those accounts from lead data and marks them _derived: true, making the discrepancy visible rather than silently hiding it.

Outcome
Deployed and in daily use.

The dashboard replaced an estimated 15–20 minutes of daily CRM navigation per manager. The vertical-split overview and priority calling list are both views that previously didn't exist in any form — not in Zoho, not in spreadsheets.

The most consequential finding wasn't a UI bug — it was discovering that Zoho's lead ownership model doesn't match how the team thinks about ownership. That single COQL fix unlocked the correct dataset for two of four managers and validated why a purpose-built tool is worth more than raw CRM access.
