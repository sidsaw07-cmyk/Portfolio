Context
Four managers. Everything was spread out.

The Target Account team at Growisto was using separate workflows in Zoho CRM. Managers had to switch between screens, filter accounts, and check leads one by one. It was hard to see which accounts were active, which had contacts, and which follow-ups were late.

The goal was one page where each manager could see their accounts, find priority accounts, check contacts, and open the page through a simple link without a login.

Architecture
A simple HTML page was enough to run the dashboard.

The CRM data was added to the HTML when the page was built. There was no backend or login system. The page could load with one request and could also work offline after being cached.

Engineering
Four problems I had to solve.
Finding 01
The lead filter was giving the wrong result for two managers

The first COQL query used Lead.Owner.id, which pointed to the person who created the lead. For two managers, this showed zero leads because someone else had created their records.

Before: filters by who created the lead record
SELECT * FROM Leads WHERE Owner.id = '319412...'
→ returned 0 leads for 2 of 4 managers
After: filters by who owns the linked Target Account
SELECT * FROM Leads WHERE Target_Account_Name.Owner.id = '319412...'
→ returns the correct full portfolio
Finding 02
Maira's data needed 15 separate requests

Zoho's COQL API returns up to 200 records at a time. Maira's portfolio had 2,958 leads, so it needed 15 requests. The script checked more_records before getting the next set. Siddharth needed 8 pages, Himanshi 7, and Chitrakshi 4.

Finding 03
Some large API responses were cut off

Some large responses were cut off while being saved. I added a recovery step that found the last complete record, fixed the JSON, and loaded it again. One 63 KB file recovered 189 of its 200 records.

Finding 04
22 accounts appeared in leads but not in the account list

Chitrakshi's account query returned 333 records, but her leads had 22 more account IDs that were missing from the list. The build script takes those accounts from the lead data and marks them _derived: true so they are not lost.

Delivery
What was built.
📊
Vertical-split overview
Status was split by vertical (Amazon/D2C vs B2B/SaaS) for each manager. This view was not available in the CRM.
📞
Priority calling list
Accounts ranked: overdue NSD → due today → warm → cold. Top contact pre-loaded per row with one-click WhatsApp and LinkedIn.
🔔
Nurture reminders
Next Step Dates from CRM were shown as overdue, due today, or upcoming and sorted automatically.
📋
Full account table
The account table could be sorted, searched, and filtered. Each row could be opened to see all contacts.
🎯
POC coverage bar
Shows the percentage of working accounts that have at least one contact, making gaps easy to spot.
🔄
Auto-refresh pipeline
PowerShell + Windows Task Scheduler. Full fetch → build → deploy cycle runs daily at 8:30 AM without manual steps.
Outcome
Used by the team every day.

The dashboard saved each manager an estimated 15–20 minutes of daily CRM navigation. The vertical view and priority calling list were new and were not available in Zoho or spreadsheets.

The biggest issue was not the design. It was how Zoho assigned lead ownership. The team looked at ownership differently from the CRM. Fixing that COQL query gave two of the four managers the correct lead data.
